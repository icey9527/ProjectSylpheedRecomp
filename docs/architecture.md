# 代码结构与修改位置

## 当前实际目录

```text
repo/
  src/app/                手写宿主入口及 ReXApp 配置
  src/input/              SDK 输入事件适配
  config/                 函数发现等分析修复
  assets/                 匹配的完整开发镜像、MAP 和 PDB
  scripts/                生成、检查、符号查询工具
  docs/                   结构、构建、维护及路线图
  generated/              自动生成的 PPC 转译代码（跟踪，不手改）
  out/                    CMake 构建结果（忽略）
  CMakeLists.txt
  CMakePresets.json
  project_sylpheed_manifest.toml
```

开发镜像和 MAP/PDB 在仓库 `assets/`，生成源码也跟踪。完整符号索引、codegen 缓存、完整资源包和构建结果不跟踪；生成文件通过工具重建，不手动修改。
手写宿主入口已移到 `src/app/`，CMake 已同步源文件路径。

## 怎样按模块组织

按符号查询分类是有用的，但不能按名字直接拆散生成 C++。
生成器按大小分文件，重新生成会重新安排代码；移动或改名会破坏自动化和注册关系。
函数也可能因链接器合并而拥有多个名字，原来的源文件结构无法仅靠函数名完整恢复。

维护采用两层：生成代码保持原样；手写补丁、配置和宿主适配按职责建目录。
只有出现真实代码时才新增目录，建议如下：

| 内容 | 后续位置 | 判断依据 |
| --- | --- | --- |
| 启动、窗口、路径、运行时配置 | `src/app/` | ReXApp 生命周期与宿主入口 |
| 手柄与键盘输入适配 | `src/input/` | SDK 输入驱动接口，不依赖游戏补丁地址 |
| 特定游戏行为修正 | `src/patches/<模块>/development/` 或 `retail/` | 按版本绑定地址、符号、调用关系和缺陷 |
| 与游戏地址无关的共用实现 | `src/patches/<模块>/common/` | 经验证两版适用的纯共用逻辑，通过版本接入调用 |
| 新增宿主功能/调试工具 | `src/features/<模块>/` | 已确认 SDK 接口及实际功能需求 |
| 经验证需要的宿主系统适配 | `src/platform/windows/` | Windows API 与平台边界 |
| 一般函数边界/跳转配置 | `config/` | 分析诊断与镜像证据 |
| SDK 指令/运行时实现修复 | 单独维护的 SDK 源码或可重复补丁 | SDK 层问题；不能藏在 generated |

MAP 的 `2DGrpLib` 可作为 UI 调查线索，`xaudio/xact` 可作为音频线索，`xgraphics/d3d9` 可作为图形线索。
这些是“检索分组”，不等于已证实的修改范围；实际补丁目录要在检查调用关系后决定。
新增源码时同时更新 CMake 源文件列表；通过 SDK 官方注册/替换接口接入，不能仅增加一个未调用的函数。
现有 config 根目录中的两个修复文件属于当前开发输入；未来零售分析配置独立放 `config/retail/`。
不为了形式创建空目录；出现实际代码/配置再添加。不同镜像的地址接入分别维护，共用逻辑只在验证行为一致后复用。
名字分类属于检索视图，不能替代调用关系和地址认证；没有零售符号也可以按已确认功能职责组织手写代码。

## Xbox 依赖如何运行在 Windows

生成代码仍表达 Xbox 的寄存器、内存及调用语义，ReXGlue 运行时负责提供相应的内核/API 与设备支持。
Windows 图形默认采用 SDK 的 D3D12 后端；输入、音频等依赖使用 SDK 选定的实现。
所以首先是“生成代码 + ReXGlue 运行时 + 完整开发 SDK”构建和运行，而不是逐个把 Xbox 库替换成 Windows 库。

只有基线运行暴露具体缺口、性能或功能需求时，才做局部宿主适配。
这类修改必须考虑数据布局、调用约定、线程/回调、端序及错误行为，不能因名字像 Windows 函数就直接替换。
目前 Windows x64 Debug 宿主已编译/链接通过，开发版调试菜单已显示。
Fiber 生命周期通过配置接入 SDK 原生实现，见 fiber-fix.md；下一步按输入与场景的实际缺陷推进局部修复。

`src/patches/input/development/vibration_trace.cpp` 是开发镜像的可选诊断接入：以强符号覆盖 `sub_82338D40` 的生成弱别名，调用 `__imp__sub_82338D40` 保留原实现。生成宏明确保留了这个原始入口，因此重新 codegen 不会覆盖手写接入。该文件只记录命令，不是震动行为修复；升级镜像须重新核对地址。

`src/patches/movie/development/movie_fallback.cpp` 同样保留原入口，处理当前不可用电影的跳过和创建失败。它复用原游戏结束清理与场景通知，原播放器仍未完整支持；地址和开关见 [电影与标题](title-and-vibration.md)。
