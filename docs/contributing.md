# 修改、验证与提交规则

每次修改都需要具体目标与完成条件；本地任务计划位于仓库外层 `plans/`。
计划应包含地址/符号、涉及文件、证据、步骤、验证和未完成项。交接写入外层 `HANDOFF.md`。
同时维护 `progress/milestones.json`：任务变更更新当前工作/下一步，验收完成记录日期与证据。
面板自动计算当前清单完成率；不得把构建成功当游戏可运行，不把试玩版加入日常验收管线。
每轮汇报当前阶段、真实已完成事项、剩余阻塞及下一步，约一分钟以上的工作持续给出简短进展。

1. 修改前查看 `git status`，识别其他人的未提交改动，避免覆盖。
2. 手写修改放在 `src/`、`config/`、`scripts/` 或 `docs/`；禁止手改 `generated/`。
3. 分析配置变化后运行 codegen，保留日志；脚本会额外检查生成代码中的未解析调用致命占位。
4. codegen 退出 0 不证明语义正确；单独记录指令警告、构建结果和实际运行结果。
5. C++、CMake 或目录路径变化后，在可用环境进行 configure/build；缺环境时明确标记“未构建”，不能写“测试通过”。
6. 提交前检查 `git diff`、`git diff --check` 和待提交文件，禁止提交游戏文件、符号原件、完整本地索引、构建结果、凭据或本机绝对路径。
7. 一个提交对应一个清楚的问题。信息描述“做了什么、为什么”；复杂修复在提交正文或文档记地址/符号、验证及限制。
8. 用户已授权维护并推送本仓库：完成必要验证、更新文档与本地交接后提交，并推送到现有 `origin`；推送后确认本地与远端一致。

允许：`docs: explain Windows toolchain prerequisites`、`fix: seed MAP-validated function entry 0x...` 等清楚的信息。
不允许只写“修好了”“改了一下”，或只提交临时修改而不说明剩余问题。

## 重做、撤销与返工

使用新提交表达返工；已推送的历史不擅自 amend、reset 或强推。
需要撤销时优先 `git revert`，保留撤销原因。
对未完成的工作，在计划和交接中标注当前状态，不把失败尝试说成完成。
生成器/SDK 有变动时记录准确版本或 commit，并说明哪些输出需要重新生成。
对 SDK 的永久修复必须保留可重复应用的源码改动或补丁，不能只替换本机 rexglue.exe。
