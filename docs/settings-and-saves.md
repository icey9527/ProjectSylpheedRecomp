# 字幕设置与存档

原资源根 `config.ini` 管理系统表和语言映射。当前文件没有字幕开关。`dat/tables/<语言>/GP_MOVIE.tbl` 指定字幕表、字体、位置和字号；`dat/GP_MOVIE/<语言>/SUBTITLE_*.tbl` 保存文字和时间段，也不保存玩家开关。

玩家设置存在原游戏二进制 `SystemData` 中：`Setup`（`0x82336178`）通过 `XUserReadProfileSettings`（`0x8265DB38`）读取标题专用档案数据；`Load`（`0x823357E8`）恢复字幕字段 `+76`，无有效数据时走原默认初始化。`Save`（`0x82335090` / `0x823354C0`）写回该档案。三个 SystemData 函数均属 `SystemData.obj`，公共原名/地址一致、模块位置一致；XUser API 属 `Xonline:profile.obj`，公共与模块原名/地址一致。

`OnStart`（`0x821E9808`）按原 Xbox 偏移读取 `+76` 并写入电影对象的 `+108`，非零才创建文字对象。已观测到两次过场均解析出 16 个时间条目，但档案门控为关闭；尚无证据表明重编译改变了结构偏移。模拟器与本程序的用户数据目录不同，原版正常显示的具体设置值仍需比较相同开发镜像和档案，不能仅凭画面推断字段错位或 SDK 损坏。

PC 侧可在 EXE 同目录 TOML 中选择：

```toml
movie_subtitles = "on" # on / off / game
```

默认开启，只调整当前电影门控，保留原字体、计时和绘制；`game` 保留原档案行为，不强制覆盖设置。它不改原档案，也不需要把二进制设置转换成 INI。边界测试验证精确调用点、单字节修改、PPC 上下文透传、不同模式与作用域恢复；新版 Release 过场记录到门控开启、16 条字幕及有效文字对象，玩家答复有效。验收限于本次观察的过场，不代表所有语言、影片或完整任务都通过。

## 保存位置

SDK 将原游戏的用户/内容 API 映射到 Windows 文件系统，继续保存游戏自己的数据格式，不使用模拟器内存快照。默认 `user_data_root` 是“文档/project_sylpheed”；可在 TOML 覆盖，相对路径仍以 EXE 目录为基准。受控诊断脚本使用单独目录，因此不会自动共享双击启动时的存档。

当前开发标题 ID 为 `535107D4`，SDK 用户名为 `User`。游戏设置位于 `<user_data_root>/535107D4/profile/User/63E83FFF` 等标题专用档案文件。内容存档位于 `<user_data_root>/<用户 XUID>/535107D4/00000001/game01/savedata` 或其他槽位，同时有内容头文件和缩略图。SDK 创建这些容器目录；游戏写入 `savedata`，不是仅靠文件名即可认定任务进度正确。

已有实际档案及两个槽位文件；完整任务后的保存、退出重启、读档恢复还没有验收。不要删除档案来“修字幕”，也不要直接覆盖模拟器存档；将来迁移需单独检查版本、用户与容器布局。

## 渲染扩展与待办

SDK D3D12 路径提供 `draw_resolution_scale_x` / `draw_resolution_scale_y`（默认 1），可作为提高内部渲染分辨率的入口；扩大窗口尺寸本身不等于提升内部画质。此游戏在更高倍率下的 HUD、特效、资源占用尚未验证。

120 FPS 需要核查游戏更新步长、物理、动画、输入、脚本和音画同步，不能仅关闭 VSync 或将显示窗口改为 120 Hz 就认定适配完成。先稳定现有帧率，再实施高分辨率和高帧率的独立计划。

视频仍随机卡顿并偶有断音；音频队列已观察到供给停顿，可能涉及更广的解码/混音/调度/帧同步管线，根因未确定。按当前要求暂缓性能修复，保留诊断与证据。
